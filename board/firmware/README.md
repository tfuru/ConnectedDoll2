# オーディオストリーミングスタンド開発ボード ver.2
XIAO ESP32C3 に TFカード, RTC, オーディオアンプ  などを追加したオーディオストリーミングボード

## 機能概要

本ファームウェアは、以下の周辺モジュールを統合制御し、BLEを介したファイルの送受信、定時スケジュール再生、スイッチによる割り込み音声トリガー、アナログ音量調節を提供します。

* **音声再生 (WAV/MP3 ハイブリッド対応)**
  * TF（MicroSD）カードに保存された音声ファイルをI2Sオーディオアンプ (MAX98357A) を経由してスピーカーから高品質再生します。
  * ファイルはデコード負荷の低い **WAV形式を優先的に再生** し、存在しない場合は **MP3形式** を探して再生します。
* **BLE通信 (時刻同期・ファイル転送)**
  * BLE経由でスマートフォン等の端末から音声ファイルを受信し、直接TFカードへ保存します（MTU最大517バイト対応）。
  * BLE経由で現在の正確な日時を取得し、RTC（リアルタイムクロック）へ反映します。
* **定時スケジュール再生 (RTC監視)**
  * 高精度RTC DS3231MZを1秒ごとに監視し、設定された定刻（初期値：毎日 12:00:00）に自動で `/alarm.wav` (無ければ `/alarm.mp3`) を再生します。
* **物理UIコントロール**
  * **タクトスイッチ (外部割り込み検知)**: 物理ボタン押下時に遅延なく `/trigger.wav` (無ければ `/trigger.mp3`) の再生をトリガーします。
  * **アナログボリューム (可変抵抗)**: アナログ入力（ADC）により、オーディオアンプの出力音量をリアルタイム（0〜21段階）に調整します。

## 動作インジケータ (LED仕様)

オンボードのフルカラーLED (WS2812B) の点灯パターンによって、現在のシステムの動作状況を一目で確認できます。

| LEDの表示状態 | システム状況 |
|---|---|
| 🟢 **緑色でゆっくり明滅 (呼吸パルス)** | 待機状態 (アドバタイズ中 / 未接続) |
| 🔵 **青色で常時点灯** | BLE接続中 (待機) |
| 🔴 **赤色で高速点滅 (100ms周期)** | BLE経由のファイルデータ受信・転送中 |
| 🟡 **黄色で常時点灯** | スピーカーから音声 (WAV/MP3) 再生中 |

## BLE通信仕様 (通信プロトコル)

スマートフォンなどのセントラル（アプリ側）から以下のUUIDを使用して基板（`ConnectedDoll_Audio`）へアクセスします。

* **サービスUUID**: `4fafc201-1fb5-459e-8fcc-c5c9c331914b`

### キャラクタリスティック定義

#### 1. 時刻同期・取得用 (`beb5483e-36e1-4688-b7f5-ea07361b26a8` / Write & Read)
基板の時刻合わせ、および現在のデバイス時刻の取得を行います。
* **書き込み (Write)**: 以下のいずれかのフォーマットでデータを書き込んで時刻を同期します。
  * **バイナリ形式 (7バイト)**: `[YYYY_high, YYYY_low, MM, DD, HH, MM, SS]`
  * **文字列形式 (19バイト)**: `"YYYY-MM-DD HH:MM:SS"`
* **読み取り (Read)**:
  * 現在のデバイス時刻（RTCの現在時刻）を文字列形式で取得します。
  * 返り値: `"YYYY-MM-DD HH:MM:SS"` (19バイトの文字列)

#### 2. ファイル転送制御用 (`e32a4e2b-fbc6-4b95-a22a-28d88b409600` / Write)
ファイル受信の開始と終了を指示します。
* **開始コマンド**: `"START:[保存するファイル名]"` (例: `"START:trigger.wav"`)
  * このコマンドを受信すると、基板は該当名でTFカード上に新規ファイルを書き込みオープンします。
* **終了コマンド**: `"END"`
  * 受信を終了し、書き込み中だったファイルを正常にクローズしてSDカードに保存します。

#### 3. ファイルデータ受信用 (`7b01d784-fb3b-4ce1-897b-cfd1264c7847` / Write)
* ファイル転送中に、バイナリデータをシーケンシャル（順次）に書き込みます。
* 受信したデータは、現在オープンされているファイルに対して即座に追記（アペンド）されます。最大517バイトの拡張MTUに対応しています。

#### 4. アラームスケジュール設定用 (`e82d0001-fbc6-4b95-a22a-28d88b409600` / Write & Read)
最大5つのアラームスロット（Index 0〜4）の設定と削除を行います。
* **アラーム設定コマンド (Write)**: `"SET:[Index],[YYYY]-[MM]-[DD] [HH]:[MM]"`
  * 例: `"SET:1,2026-07-25 15:30"` (スロット1にアラームを登録。時間になると `/alarm1.wav` または `/alarm1.mp3` を再生)
* **アラーム削除コマンド (Write)**: `"DEL:[Index]"`
  * 例: `"DEL:1"` (スロット1のアラーム設定を削除し、無効化します)
* **設定の読み取り (Read)**: 
  * 現在の全スロットの設定情報をテキスト形式で取得します。
  * フォーマット: `[Index]:[Enabled],[Time];[Index]:...`
  * 返り値の例: `"0:1,2026-07-25 15:30;1:0;2:0;3:0;4:0"` (`0` は無効、`1` は有効を示す)

#### 5. LED明るさ設定用 (`e82d0002-fbc6-4b95-a22a-28d88b409600` / Write & Read)
デバイス上のフルカラーLED (WS2812B) の輝度（明るさ）を設定および取得します。
* **書き込み (Write)**: `0`〜`255` の範囲の輝度を文字列形式（例: `"128"`) または1バイトのバイナリ形式で書き込みます。
* **読み取り (Read)**: 現在設定されている輝度を文字列形式（例: `"128"`) で返します。設定値はフラッシュ（Preferences）に保存されます。

## GPIOなど

本基板で使用している XIAO ESP32C3 の GPIO 割り当ては以下の通りです。

| XIAOピン | ESP32-C3 GPIO | 接続先・機能 | 備考 |
|---|---|---|---|
| D0 | GPIO2 | タクトスイッチ | トリガー再生用 (アクティブLOW) |
| D1 | GPIO3 | 可変抵抗 (10kΩ) | 音量調整用 (アナログ入力 / ADC) |
| D2 | GPIO4 | MicroSD MOSI | SPI通信用 (3.3Vへ10kΩプルアップ) |
| D3 | GPIO5 | フルカラーLED (WS2812B) | 5Vレベルシフタ経由でDINへ接続 |
| D4 | GPIO6 | RTC SDA | I2C通信用 (3.3Vへ1.5kΩプルアップ) |
| D5 | GPIO7 | RTC SCL | I2C通信用 (3.3Vへ1.5kΩプルアップ) |
| D6 | GPIO21 | I2S BCLK | オーディオアンプ (MAX98357A) 接続 |
| D7 | GPIO20 | I2S LRCLK | オーディオアンプ (MAX98357A) 接続 |
| D8 | GPIO8 | MicroSD SCK | SPI通信用 (3.3Vへ10kΩプルアップ) |
| D9 | GPIO9 | MicroSD MISO | SPI通信用 (3.3Vへ10kΩプルアップ) |
| D10 | GPIO10 | I2S DIN | オーディオアンプ (MAX98357A) 接続 |

* **MicroSD CS（チップセレクト）**: 基板上で直接 GND に接続されており、常時アクティブ（有効）に設定されているため GPIO ピンは消費しません。




## 開発環境
このプロジェクトは[PlatformIO](https://platformio.org/)を使用して開発されています。

- **Board:** `seeed_xiao_esp32c3`
- **Platform:** `espressif32`
- **Framework:** `arduino`

### ライブラリ
依存ライブラリは `platformio.ini` に記載されており、ビルド時に自動的にインストールされます。

### ファームウェアの書き込み
Makefileを使用してコマンドラインからビルドや書き込みを行うこともできます。
環境変数 `ENV` で対象ボードを指定できます（省略時は `platformio.ini` のデフォルトまたは全環境）。

```bash
# プロジェクトのビルド
make build

# ファームウェアの書き込み
make upload

# ファイルシステムの書き込み (dataフォルダ)
make uploadfs

# シリアルモニターの起動
make monitor

# ビルドアーティファクトの削除
make clean
```

## 推奨音声フォーマット

I2Sアンプによる音声再生時に「バチバチ」や「プツプツ」といったノイズ（または音の途切れ）が発生する場合、基板の配線抵抗やSDカードの応答遅延によるデータ破損・供給不足が起きている可能性が高いです。その場合は、以下の**軽量化フォーマット**に変換して再生をお試しください。

### 1. WAV 形式 (低CPU負荷・再生の安定性重視)
非圧縮のためCPU負荷がほぼゼロで、最も安定して動作します。立ち上がりが遅い回路（10kΩプルアップ等）では、サンプリングレートを下げてSDカードの読出頻度を抑えるのが最も効果的です。

- **推奨パラメータ**: **16 kHz / 16-bit / モノラル**
- **ffmpeg での変換コマンド例**:
  ```bash
  # 最も安定してノイズの出ない 16kHz モノラル WAV に変換する
  ffmpeg -i input.mp3 -acodec pcm_s16le -ac 1 -ar 16000 output.wav
  ```

### 2. MP3 形式 (ファイルサイズ極小・BLE転送速度重視)
WAVよりファイルサイズが小さいため、BLE転送時間が極めて短くなります。再生時のバチバチ音を防ぐため、ビットレートを下げて転送量とデコード計算の両方を最小化します。

- **推奨パラメータ**: **64 kbps (CBR固定) / 22.05 kHz / モノラル**
- **ffmpeg での変換コマンド例**:
  ```bash
  # 転送量と計算負荷を最小化する 64kbps固定 モノラル MP3 に変換する
  ffmpeg -i input.mp3 -codec:a libmp3lame -b:a 64k -ar 22050 -ac 1 output.mp3
  ```
